# Daily Notes · Agent 写作约束

本文件在 Daily Notes 插件启用期间生效，约束 Antigravity Agent 对每日笔记的读写方式。每日笔记是用户的手写资产，Agent 只做增量协作。

## 1. 写前必读

- 修改或覆盖任何一天的笔记之前，必须先调用 `daily_notes_get` 读取最新内容与 `revision`。
- 写入工具一律显式传入最新的 `expected_revision`，让乐观锁生效；不要凭记忆或旧上下文里的版本号写入。
- 目标日期不明确时按「今天」（本机本地时区自然日）处理，并在回复中写明实际操作日期。

## 2. 优先增量，慎用整篇覆写

- **首选** `daily_notes_append`：仅在文档末尾或指定小节末尾追加新内容，不会触碰用户已写的段落。
- **次选** `daily_notes_toggle_todo`：只切换匹配的那一行复选框状态，用于勾选或取消勾选已有待办。
- **最后才用** `daily_notes_update`：仅在确实需要重写整篇（`mode: "replace"`）或替换某个小节（`mode: "replace_section"`）时使用，并必须提供 `summary` 说明改了什么。

## 3. 禁止事项

- 严禁虚构不存在的历史笔记内容、日期或待办项；不确定就先读。
- 严禁擅自删除或重排用户手动编写的内容块（标题、列表、代码块、表格、图片引用）。
- 严禁把图片改成外部 URL，附件统一沿用 `/api/attachments/<id>` 形式。
- 不提供批量删除笔记、清空数据库或执行任意 SQL 的替代路径，Agent 只通过工具读写。

## 4. 冲突处理（`REVISION_CONFLICT`）

- 收到 `REVISION_CONFLICT` 时立刻停止覆盖，先重新 `daily_notes_get` 取回最新版本。
- 在对话中向用户展示冲突的两侧内容（用户的当前版本 vs 你准备写入的内容），说明差异，等用户选择「保留我的」「采用 Agent 版本」或「合并后写入」再继续。
- 绝不通过连续重试或猜测版本号的方式绕过冲突静默覆盖。

## 5. 内容规范

- 正文统一 GFM：任务清单用 `- [ ]` / `- [x]`，代码用带语言的围栏代码块，日期双链写完整 `[[YYYY-MM-DD]]`。
- 标签直接写在正文里（如 `#perf`），不要另建标签字段；`#` 后不留空格。
- 一次写入聚焦一个主题，标题层级从 `##` 起，避免与当日手写的一级标题抢层级。
- 追加内容前若文档已有内容，用空行与上文分隔，保持可读性。

## 6. 写后回执

- 写入成功后，回复中明确告知：写入的日期、最新 `revision`、所属小节（如有），以及「如不满意可在侧边栏一键撤销」。
- 只汇报真实发生的变化，未写入就说明原因（冲突、日期非法、附件校验失败等）。
